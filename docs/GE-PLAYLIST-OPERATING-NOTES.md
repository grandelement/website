## 2026-10-26 Access Codes — no third Worker required
The live source architecture already contains a secure owner publisher endpoint `/manage/access-codes` in `backroom/publisher-worker.js`. It verifies the Back Room session then forwards `GET` and `POST` to GE Vault's `/v1/admin/access-codes`, where `vault-worker/src/index.js` manages hashed code secrets, permitted scopes, issue/edit/suspend/revoke/delete/master states, expiration and use limits and persistent D1 `access_code_content` song grants. **DO NOT create a second, competing access-code Worker or database without an explicit security/operations migration plan.** The playlist master still belongs in GitHub.

Access Codes editor in `backroom/index.html` now has a genuine expandable `MUSIC · PLAYLISTS & SONGS` panel (`brAccessMusicCategory`) under the existing expandable PERMISSIONS and EXPIRATION & LIMITS controls. It fetches the same GitHub GE owner playlists as Back Room Music and renders a checkbox for each (`brAccessPlaylistChoices`). `LOAD CHECKED PLAYLISTS` unions their paths, validates all against the website manifest and the D1 250-song grant limit, and loads the per-song checkboxes; then the owner must issue or update the actual code. No unchecked playlist side effect is saved. Album filter, album checkboxes, individual song search and selected track list all work against `assignedSongPaths`. The saved code body deliberately persists explicit `track_paths` with `playlist_ids: []`, preventing mutable playlist IDs from silently granting newly added tracks or undoing a deselected track's restriction.

Permissions provided by the existing service: ENTIRE WEBSITE, RADIO, MUSIC, ALBUMS and GAMES. The durations are from first use, from activation, fixed expiry or never; max uses; master enable; suspend/revoke/delete. These are real backend scope/grant records, but the public website/game/music consumers must independently enforce them; do not claim universal gating across every page based on existence of checkbox alone.

**CRITICAL PRE-RELEASE LIMITATION:** the current website Radio Gate calls `/v1/public/access/redeem` with `{code,scope:'radio'}` only. A code with nonempty `track_paths` requires `track_path` or authorized `playlist_id` in the Vault redemption request. Thus playlist/song-restricted codes **cannot yet** unlock the standard Radio Gate and provide tailored playback; a Radio-only broadcast isn't a personalized playlist. Integrate the fan Music/player redemption path with code-selected track scope and server verification; protect private MP3 delivery before claiming paid song access. DO NOT bypass this requirement by making restricted codes unlock unrestricted live Bangers Radio. Verify response with real owner issued code and distinct fan browser session, and verify content outside the grant is rejected.

The app's legacy LOVE Radio Gate password is a separate system and should not be silently tied to issued owner access codes. Owner code secrets should never be logged, committed to GitHub, or shown after their one-time issuance screen.
